**How it meets the brief:**
- **Features:** you enter a US city and get its parks in a list and on a map. Moving the map loads parks for the new area. Selecting a park shows its name, address, description, amenities, hours and images.
- **Missing information:** OpenStreetMap often has no description, hours, or images. The app shows "Hours not available" and similar labels instead of making anything up. Unnamed parks and records with bad coordinates are skipped.
- **Speed and duplicate requests:** calls to OpenStreetMap time out and retry, and respect "try again later" replies. Map moves wait until you stop panning, a new search cancels the old one, and repeat searches are answered from a short-lived in-memory cache.
- **Security:** only the backend calls outside services, so no keys or credentials reach the browser. It allows only your frontend's address, accepts only GET requests, checks every input, limits requests per user, and never shows internal error details.
- **Maps and locations:** parks stored as outlines (not just points) are handled, parks near the edge of the map aren't dropped, duplicates are removed, and nearby markers are grouped into clusters.
- **Accessibility:** the list works fully by keyboard without touching the map, focus is always visible, and the selected park is marked with text and a ★, not just colour.

**Decisions and trade-offs to know about:**
- **When live data is down:** the app shows parks from `assets/parks.sample.json` with a notice. If there's no sample data for that area, it returns an error rather than an empty list, so it never falsely says "no parks here".
- **Sample file:** `assets/parks.sample.json` didn't exist, so I created it with 6 parks, some with fields deliberately left out. The Prospect Park image is the placeholder URL from your brief, which doesn't load, so the app shows "Image could not be loaded."
- **Usage limits:** the public OpenStreetMap services have fair-use limits. For real traffic, set `PARKFINDER_CONTACT_EMAIL` in `backend/.env`, and self-host those services or switch providers. The addresses are configurable.

API calls are now logged locally, and one request ID lets you trace a call from the browser, through the backend, to OpenStreetMap and back. All 180 backend tests and 80 frontend tests pass, and typecheck and the production build are clean.

**How it works:**
- The browser sends an `X-Request-ID` with each call. The backend reuses it if it's safe, otherwise creates its own.
- Every backend log line written while handling that request carries the ID, and the ID comes back in the response header and in every error body.
- When an error shows up in the UI, it now includes a **Reference ID**, so a user can report exactly which call failed.

**Backend log:** `backend/logs/api.log` has one JSON record per line, rotated at 5 MB with 5 old files kept (about 30 MB at most). It records:
- every API request: method, path, query, status, time taken, client IP;
- every call to Nominatim or Overpass, including each retry: status or timeout type, attempt number, time taken;
- cache hits and misses, provider failures, and a summary of each search;
- full error details for unexpected failures. These stay in the log and are never sent to the browser.

**Frontend log:** the last 50 calls are kept in memory. You can see them in the browser dev tools as `window.__parkfinderApiLog`, and in dev mode each call is also printed to the console.

**Safety:**
- Values of parameters that look like credentials (key, token, secret and similar) are replaced with `***`.
- A request ID sent by the browser is only accepted if it's short and uses safe characters, so nobody can inject fake log lines.
- Client IP addresses are logged. If your privacy policy doesn't allow that, it's one field to remove or hash in `main.py`.

I checked it live: a Boise search showed Nominatim succeeding, a cache miss, three Overpass timeouts, and a 503, all under the same ID. The 503 happened because the public Overpass server wasn't responding and there's no sample data for Boise, not because of this change. That run also showed the log only said "timeout", so it now records the timeout type (for example `ConnectTimeout` vs `ReadTimeout`).

To find everything for one call:
```powershell
Select-String -Path backend\logs\api.log -Pattern "<request-id>"
```
